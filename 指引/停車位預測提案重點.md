# 智慧停車 AI Agent 提案重點

## 1. 作業核心要求

專題必須形成完整的真實世界應用，核心組合為：

> AI Agent + Domain Knowledge + Data Analytics + Real-World Application

不能只訓練單一模型或製作聊天機器人。系統必須能理解需求、取得資料、執行分析、結合停車領域知識進行決策，並提供可驗證的預測或建議。

### Proposal 必備內容

1. **Abstract**：依 Motivation、Challenge、Solution、Method、Evaluation、Expected Outcomes 建立完整研究故事。
2. **Introduction**：說明研究重要性、背景、問題、既有限制、創新與預期貢獻。
3. **Related Work**：約一半 AI 技術、一半停車領域知識，並包含 Article Summary Table。
4. **Deep Research**：五個核心思維模式、三個重要專業爭論、十個深度理解問題。
5. **Proposed Scheme**：包含 System Architecture、Flowchart 與有行號的 Pseudocode。
6. **References**：重要論述需有可核對的原始來源。

### Proposal 評分比例

| 項目 | 比例 |
|---|---:|
| Introduction | 20% |
| Related Work | 20% |
| Deep Research | 20% |
| AI Agent 與系統架構 | 20% |
| Flowchart、Pseudocode、技術可行性 | 15% |
| GitHub、DESIGN.md、完整度 | 5% |

## 2. 建議專題定位

### 題目

**基於多源資料分析與領域知識推理之智慧停車 AI Agent：以臺中市剩餘車位預測為例**

英文題目：

> A Smart Parking AI Agent Based on Multi-source Data Analytics and Domain Knowledge Reasoning: A Case Study of Parking Availability Prediction in Taichung City

### 使用情境

使用者輸入目的地、預計抵達時間、預算與可接受步行距離。系統取得附近停車資訊，預測抵達時的剩餘車位或滿位風險，再綜合距離、費率與偏好提供可解釋的推薦。

### 核心研究問題

1. 歷史車位與時間特徵能否預測未來 30／60 分鐘的剩餘車位？
2. 加入天氣、星期與假日等外部特徵，是否能改善預測？
3. Agent 能否將預測、費率、距離與滿位風險整合成有證據的推薦？

### 研究缺口

「停車位預測」本身不是全新題目。較合理的研究缺口是：

> 如何將臺中在地停車資料、短期車位預測、資料品質、領域限制及個人化偏好，整合成可驗證且可解釋的 AI Agent 決策流程？

正式提交前仍須透過文獻與既有系統比較，確認此研究缺口成立。

## 3. 建議研究範圍

### 資料對象

- **路外停車場**：以停車場為單位，預測剩餘車位數、占用率與滿位風險。
- **路邊停車格**：以車格或路段為單位，預測占用狀態或可用車格數。

兩類資料粒度與品質不同，應分開建立、訓練及評估模型，再由 Agent 決策層整合推薦。

### MVP 範圍

- 先選一個資料較完整的臺中區域，不宣稱涵蓋全市。
- 納入數個可靠的路外停車場與一批狀態完整的路邊車格。
- 第一版先預測未來 30 分鐘。
- 以距離、費率、剩餘車位與滿位風險進行排序。
- 驗證成功後再擴充至 60 分鐘及更多區域。

## 4. 資料可行性與風險

### 可用資料方向

- 臺中市路外停車場位置、容量及剩餘車位相關資料。
- 臺中市路邊車格的路段、車格、座標與占用狀態。
- TDX 停車動態資料。
- 天氣、假日、停車費率及地理位置等外部資料。

### 必須先驗證

1. API 是否穩定回傳精確剩餘車位，而非只有滿車率燈號。
2. 路邊車格資料的涵蓋率、更新時間及故障狀態是否可靠。
3. 是否已有可用歷史資料；若沒有，必須定期擷取即時 API 自行累積。
4. 停車場或車格識別碼能否跨時間穩定對應。
5. 授權、存取頻率、API Key 與使用限制。

### 資料處理原則

- 保存原始資料、擷取時間、來源更新時間及清理後資料。
- 感測器故障、未知與空位必須分開處理。
- 缺少觀測不等於剩餘車位為零。
- 舊資料不可直接視為目前狀態，必須檢查資料新鮮度。
- 模型實驗資料與臺中實際部署資料不同時，必須明確區分。

目前已取得的 UCI Parking Birmingham 歷史資料可用於模型流程與基準實驗，但不能宣稱為臺中市實際預測成果。

## 5. 系統架構

| 編號 | 模組 | 責任 |
|---|---|---|
| ① | User Interface / GIS | 輸入目的地、時間、預算與步行限制 |
| ② | Agent Orchestrator | 解析意圖、拆解任務、選擇資料與工具 |
| ③ | Data Connectors | 取得路外、路邊、費率、天氣與地理資料 |
| ④ | Data Quality & Storage | 清理、時間對齊、儲存及追蹤資料新鮮度 |
| ⑤ | Prediction Engine | 預測剩餘車位、占用狀態及滿位風險 |
| ⑥ | Domain Decision Engine | 套用容量、收費、距離、偏好及風險規則 |
| ⑦ | Recommendation Agent | 篩選、排序並產生推薦理由 |
| ⑧ | Output & Evaluation | 顯示地圖、預測曲線、推薦與實驗指標 |

LLM 負責需求理解、任務規劃與說明；數值預測交由可重現的模型完成，不應讓 LLM 自行產生車位數。

## 6. 核心流程

```text
使用者輸入目的地、抵達時間與偏好
  → 尋找附近路外停車場與路邊路段
  → 檢查資料完整性與新鮮度
  → 清理資料並建立特徵
  → 呼叫對應的預測模型
  → 預測剩餘車位與滿位風險
  → 套用容量、費率、距離及偏好規則
  → 排序候選方案
  → 顯示推薦理由、資料時間與限制
  → 保存預測結果供事後驗證
```

若資料失效、模型不可用或沒有合格候選，系統必須說明限制並提供替代查詢，不可偽造預測。

## 7. 領域知識規則

| 領域知識 | 系統規則 |
|---|---|
| 停車容量 | 預測剩餘位不得小於 0 或大於總容量 |
| 車格狀態 | 故障與未知狀態不可當成確定空位 |
| 時間週期 | 平日、假日、尖峰與離峰需分開建模或設為特徵 |
| 空間關係 | 鄰近停車資源可能共享或轉移需求，需用資料驗證 |
| 收費制度 | 根據計費單位、時段與上限估算停車成本 |
| 資料不確定性 | 顯示資料時間、模型誤差與信心程度 |

這些規則屬待驗證的領域假設，不可直接宣稱適用於所有停車場。

## 8. 模型與實驗設計

### 比較模型

| 類型 | 方法 | 目的 |
|---|---|---|
| Baseline 1 | Persistence | 檢查複雜模型是否優於最新觀測值 |
| Baseline 2 | 同星期、同時段歷史平均 | 檢查時間週期是否足以預測 |
| Model 1 | Random Forest | 建立非線性基準模型 |
| Model 2 | XGBoost | 評估梯度提升模型 |
| 選用 | LSTM／時空模型 | 僅在資料量與時間跨度足夠時使用 |

### 預測目標

- 未來 30／60 分鐘剩餘車位數。
- 未來 30／60 分鐘滿位風險。
- 路邊車格占用狀態或路段可用車格數。

### 評估指標

- 車位數預測：MAE、RMSE。
- 滿位風險：Precision、Recall、F1-score。
- 推薦品質：Top-k 可用率、距離與預估費用比較。
- Ablation：移除天氣或時間特徵，檢查特徵貢獻。

### 實驗限制

- 必須依時間切分訓練、驗證與測試集。
- 不得使用預測時間之後才知道的資料。
- 路外與路邊模型先分開評估。
- 所有模型都必須與簡單基準比較。
- 預測值必須與後續實際觀測比較，不能只展示合理案例。

## 9. 分階段交付

### P1：資料驗證

- 串接 API，建立統一欄位、排程擷取與歷史資料庫。
- 產出資料字典、資料品質報告及初步地圖。

### P2：預測模型

- 分別建立路外與路邊模型。
- 完成基準模型、模型比較及誤差分析。

### P3：Agent 決策

- 解析自然語言需求。
- 整合預測、距離、費率與偏好，產生可追溯推薦。

### P4：展示與驗證

- 完成 GIS 地圖、即時資訊、預測曲線及推薦清單。
- 比較只看即時空位與使用預測推薦的差異。
- 完成 README、DESIGN.md、Proposal、PPT 與實驗報告。

## 11. 提案撰寫注意事項

- Proposal 尚未完成的結果只能寫 Expected Outcomes，不得虛構實驗結果。
- 不宣稱「目前沒有智慧停車預測系統」，而應以文獻比較界定具體研究缺口。
- 引用原始論文與政府資料頁，不直接引用對話中的搜尋摘要。
- 清楚區分模型、Agent、領域決策規則與使用者介面。
- 清楚揭露資料範圍、品質、授權、限制及模型適用範圍。
